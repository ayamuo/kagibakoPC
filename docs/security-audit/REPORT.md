## KAGI-01：ドメイン照合が別所有者のサイトを許可します

対象：`app/js/domain.js:64–87`、`app/js/app.js:2568–2615`、`desktop/MainForm.cs:389–409,434–435`、`android/app/src/main/assets/js/autofill-page.js:124–130,156–189`。

`registrableDomain()` は手書きの一覧にないサフィックスについて末尾2ラベルを返します。`co.id`、`com.mx` は一覧から漏れており、登録URLからサイトの所有者を示すラベルが落ちます。`hostAllowed()` はその過大な範囲に属する任意のサブドメインを許可します。PCに渡すリストも完全一致指定に変換されません。

再現結果（以下は文字列だけの検証で、これらのサイトには接続していません）：

```text
登録: https://audit-victim.co.id/
許可リスト: ["co.id"]
入力先: audit-attacker.co.id
結果: true（許可）

登録: https://audit-victim.com.mx/
許可リスト: ["com.mx"]
入力先: audit-attacker.com.mx
結果: true（許可）
```

両サフィックスは公式の [Public Suffix List](https://publicsuffix.org/list/public_suffix_list.dat) に掲載されています（取得時の版：2026-11-13_14-44-35_UTC）。同じサフィックスの下であることは、同じ所有者である根拠になりません。

攻撃条件：該当サフィックスのサイトを利用者が登録済みで、攻撃者が同じサフィックス配下の別サイトを用意し、利用者がそこで該当アイテムの自動入力を実行することです。ドメイン不一致の確認を経ずに秘密を渡す可能性があります。PC側には登録済みURL自体のブランド警告もありますが、任意のサイトを保護する一般的な対策にはなりません。

推奨修正：ワイルドカード・例外規則・PRIVATEセクションを扱うPSL実装と更新済みデータを同梱してください。ドメイン境界を確定できない場合は広げず、登録ホストとの完全一致に倒してください。単に2件を一覧へ追記するだけでは同種の漏れが残ります。

## KAGI-02：ダイアログを残すだけで自動ロックが停止します

対象：`app/js/app.js:181–184`。

`checkAutoLock()` は `.overlay` が存在すれば、最後の操作時刻を調べる前に戻ります。ダイアログは実際に操作されていなくても存在し続けるため、設定・ヘルプなどを開いて席を離れたとき、自動ロックが成立しません。

再現手順：

1. 検証用の `.kagi` を正しいマスターパスワードで開きます。
2. 自動ロックを5分に設定し、通常のモーダルを開きます。
3. 追加の操作をせずに、自動ロック判定上の時刻を1時間進めます。
4. アプリが登録した実際の `checkAutoLock` コールバックを実行します。

Edgeでの結果：`screen: "main"`、検証用パスワードは金庫内に残っています。対照実験としてモーダルを閉じ、再びタイムアウト条件を満たすと `screen: "unlock"`、`vaultCleared: true` になりました。実時間を1時間待つ代わりに、テスト内で `Date.now()` を進めています。

攻撃条件：既にロック解除されたアプリがダイアログを開いたまま放置され、第三者が端末を操作できることです。OSの画面ロック解除やマスターパスワードの突破を示すものではありません。Windowsのシステムロック通知は別経路です。

推奨修正：モーダルの存在でタイムアウトを無効にせず、操作イベントだけで最終操作時刻を更新してください。タイムアウト時はダイアログも閉じ、進行中の非同期処理がロック後に秘密の表示を復活させないよう、セッション世代番号などでキャンセルしてください。

## KAGI-03：HTTPSからHTTPへの変更を検出しません

対象：`app/js/app.js:2577–2594`、`desktop/MainForm.cs:401–409`、`android/app/src/main/assets/js/autofill-page.js:124–130,156–189`。

自動入力の許可判定はホスト名だけで行われ、登録時のHTTPSと入力先のHTTPを区別しません。Android側は `AutofillAuthActivity.kt:50` で `webScheme` を渡していますが、選択画面で使っていません。登録URLがHTTPの場合の警告とは別の問題です。

```text
登録: https://login.example.com/
入力先: http://login.example.com/
ドメイン照合: true（許可）
```

攻撃条件：HSTSやブラウザのHTTPS強制などで防がれずHTTPページが表示され、攻撃者が通信経路を改ざんでき、利用者が自動入力を実行することです。入力先ページにスクリプトを差し込まれると、送信ボタンを押す前でも入力済みの秘密を取得され得ます。実際の中間者攻撃や資格情報の送信は行っていません。

推奨修正：URLのスキームもPC・Androidの入力直前に検査し、HTTPSで登録されたアイテムのHTTPへの自動入力は拒否してください。スキームが取得できない場合を成功扱いにせず、localhost等の例外が必要なら明示的に管理してください。

## 再実行

リポジトリのルートで以下を実行します。

```powershell
node tests/run-tests.mjs
node tests/security-audit.mjs
```

`security-audit.mjs` は、合成金庫・一時ブラウザプロファイル・127.0.0.1限定の一時サーバーを使います。Edgeを使い、必要なら環境変数 `AUDIT_BROWSER` でChromium系ブラウザの実行ファイルを指定できます。この環境でヘッドレス実行するため `--no-sandbox` を付けています。検証ページ以外の外部サイトは開きません。生成した金庫やデータをユーザーのプロファイルに保存しません。

結果は `docs/security-audit/results.json` に記録します。このスクリプトは観測結果を出力するプローブであり、終了コード0だけで脆弱性が修正済みとは判定しません。

## 対応（2026年11月15日）

| ID | 対応 |
| --- | --- |
| KAGI-01 | 手書きの一覧をやめ、公式の Public Suffix List（ワイルドカード・例外・PRIVATE を含む約1万規則）を同梱して判定（`app/js/domain.js`・`app/js/psl-data.js`）。一覧で境界が決まらないドメインは広げず、ホストとの完全一致だけを許す（PC版には `=` 付きで渡す）。 |
| KAGI-02 | ダイアログが開いていても無操作ならロックする。ロック時は開いていたダイアログを結果を返さずに捨て（`abandonAllModals`）、Esc などで続きの処理が動き出さないようにした。文字入力も操作として数える。 |
| KAGI-03 | https で登録したアイテム（スキーム省略も https とみなす）は http のページに入力しない（`insecureTarget`）。PC版はアドレスバーに `http://` が出ていれば、入力前と入力中の毎回の照合で止める。Android版はブラウザから届くスキームで止め、スキームが届かないときは確認を求める。 |

確認：`node tests/run-tests.mjs`（79件成功、上記のケースを追加）、`node tests/security-audit.mjs`（3件とも修正後の結果。ロックで捨てたダイアログが Esc で再開しないことも追加で確認）。

残る制限：Chrome・Brave・Firefox はアドレスバーで `https://`／`http://` を省いて表示するため、PC版ではこれらのブラウザの http ページを文字列から見分けられない。実際のブラウザでの確認と、「保護されていない通信」表示の読み取りは今後の課題。
